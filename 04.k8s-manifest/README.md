# 4단계. 순수 Kubernetes Manifest 로 애플리케이션 배포

`cloud-native-learning-roadmap.md` **4단계**의 작업 기록이다.

## 이 단계의 목적

**잘 배포하는 것이 아니다.** 매니페스트 1,423줄을 직접 쓰고, **그중 어느 줄이 왜 필요한지 설명할 수 있게 되는 것**이다.

```text
                    전체      주석·빈 줄 제외
  compose.yaml      202줄          91줄
  k8s/*.yaml      1,423줄         556줄
                                  약 6배
```

```text
Compose 가 안 물어보는 것을 Kubernetes 는 물어본다
  몇 개를 띄울 것인가 / 죽으면 어떻게 할 것인가
  트래픽을 어디로 보낼 것인가 / 준비됐다는 걸 무엇으로 판단할 것인가
  CPU 와 메모리를 얼마나 줄 것인가 / 업데이트할 때 몇 개씩 바꿀 것인가
  종료할 때 몇 초를 기다릴 것인가 / 디스크는 어디에 있는가

→ 정하지 않은 것이 아니라 물어보지 않았을 뿐이다
```

## Helm 을 쓰지 않는다

```text
[처음부터 Helm 을 쓰면]
  Template 안에 리소스의 실제 구조가 가려진다
  → 무엇이 왜 그렇게 됐는지 모른 채 넘어간다

[순서]
  순수 Manifest → 각 리소스 이해 → 중복과 차이를 겪음
  → Template 필요성 체감 → 그다음 Helm (7단계)
```

## 진행 방식 — 중간에 바꿨다

처음에는 매니페스트를 **AI 도우미가 써주고 사용자가 읽는** 방식으로 진행했다. 배포는 됐지만 **"읽어서 아는 것"과 "안 보고 쓸 수 있는 것"의 간격**이 그대로 남았다.

```text
2026-08-27 부터 방식을 바꿨다

  [이전]  매니페스트를 대신 써준다 → 읽는다
  [이후]  무엇이 필요한지만 알려준다 → 직접 쓴다 → 검토받는다 → 부순다
```

```text
실습 환경은 네임스페이스로 분리한다
  bookstore        실제로 도는 것. 건드리지 않는다
  bookstore-lab    실습용. 마음대로 부순다
```

## 클러스터 사전 조건

```text
StorageClass 없음        → 동적 프로비저닝이 안 된다. PV 를 손으로 만든다
                           local PV 는 nodeAffinity 로 특정 노드에 묶인다
Ingress 컨트롤러 없음     → NodePort 로 외부 접근을 만든다
master01 에 NoSchedule    → 앱 Pod 가 control-plane 에 안 뜬다
```

**클라우드였다면 셋 다 없었을 문제다.** 10단계에서 EKS 로 갔을 때 "AWS 가 대신 처리해주는 영역"과 "Kubernetes 자체 기능"을 구분하는 재료가 된다.

## 블로그 원고 순서

**개념과 실행을 한 편에 합친다.** 개념만 있는 글은 읽을 이유가 약하고, 나누면 편수가 두 배가 된다.

| # | 제목 | 합쳐지는 것 | 상태 |
|---|---|---|---|
| 1 | 매니페스트는 전부 같은 네 칸이다, apiVersion 부터 selector 까지 | 개념 + 라벨 변경 실험 | 발행 |
| 2 | Pod 하나 띄우는 데 에러를 여섯 번 봤습니다 | 개념 + 직접 쓰기 + 지워보기 | 원고 |
| 3 | 환경변수를 하나도 안 주고 Pod 를 띄운 이유 | 이미지 검증 (독립 주제) | 발행 |
| 4 | 지워도 다시 생깁니다. 그런데 배포하니 1%가 실패했습니다 | 개념 + 직접 쓰기 + 롤링 업데이트 실험 | 원고 |
| 5 | Endpoints 가 비었는데 이벤트는 하나도 없었습니다 | 개념 + 직접 쓰기 + 실험 C·4·5·6 | 원고 |
| 6 | 한 번 고쳤는데 결과가 셋으로 갈렸습니다 | 개념 + 직접 쓰기 + 심볼릭 링크 + subPath 실험 | 원고 |
| 7 | PV / PVC / StatefulSet | 개념 + 데이터 유지 (정적 프로비저닝) | 발행 · 후속 12번 |
| 8 | 잘 떴는데 요청 30번에 전부 죽었습니다 | 개념 + 직접 쓰기 + readiness·liveness·OOM 실험 | 원고 |
| 9 | 만들긴 했는데 아무도 읽지 않았습니다 | 개념 + 직접 쓰기 + Ingress·LoadBalancer·Local 실험 | 원고 |
| 10 | redis - 스키마를 만든 적이 없는데 데이터가 들어가 있습니다 | 미들웨어 (독립) | 원고 |
| 11 | PV 도 PVC 도 Bound 인데 Pod 가 안 떴습니다 | 매니페스트 10개 종합 | 발행 |
| 12 | PV 를 만들어주는 것도 결국 Pod 하나였습니다 | 동적 프로비저닝. 7번의 후속 | 원고 |
